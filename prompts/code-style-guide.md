# 易站智能 - Agent 代码风格与质量规范

**版本**：v2026.05  
**优先级**：高（代码可维护性）

每次生成或修改代码时，必须严格遵守以下规范。

### 1. 总体原则
- **清晰、可读、可维护** 是最高优先级
- 代码必须让人类开发者容易理解和接手
- 遵循“最小改动 + 增量替换”原则
- 重要修改必须说明理由和影响范围

### 2. 代码风格要求
- **注释**：关键逻辑、复杂函数、重要修改处必须添加清晰注释
- **命名规范**：
  - 变量、函数使用清晰有意义的英文命名（驼峰或下划线根据技术栈）
  - 避免使用 `a`、`temp`、`data1` 等模糊命名
- **函数/方法**：单一职责原则，一个函数只做一件事
- **缩进与格式**：保持统一（使用 Prettier 或 Black 等格式化工具）
- **错误处理**：必须有合理的异常处理和日志记录

### 3. 前端规范
- 优先使用组件化开发（复用 LoginComponent、Card 等）
- Tailwind CSS 类要合理组织，避免过长行
- 重要交互必须有加载状态、错误提示和成功反馈
- 用户操作处必须添加帮助说明（参考 user-flow-help-rules.md）

### 4. 后端规范
- Flask / FastAPI 路由要清晰分层
- 数据库操作使用连接池，避免频繁开关连接
- 重要业务逻辑抽成 Service 层
- API 返回格式统一（success, data, message, code）

### 5. 修改代码时的严格要求
- **先方案后代码**：必须先给出分析和方案
- 每次修改后提供：
  - 修改的文件列表
  - 主要变更点
  - 潜在风险
  - 测试验证清单（至少3条）

### 6. 禁止行为
- 禁止创建重复代码（尤其是登录页面）
- 禁止一次性大改核心模块
- 禁止生成没有注释的代码
- 禁止直接覆盖整个文件而不说明变更

---

**执行要求**：
本文件与 `system-core-rules.md` 共同生效。生成任何代码时都必须遵守本规范。
