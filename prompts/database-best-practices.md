# 易站智能 - 数据库设计与最佳实践规范

**版本**：v2026.05  
**优先级**：高（平台稳定性和可扩展性）

数据库是平台核心基础设施，必须严格遵守以下规范，防止用户增长后出现性能问题和隐患。

### 1. 核心设计原则
- 优先考虑**可扩展性**和**性能**
- 所有重要表必须有合理的索引
- 重要查询必须考虑未来数据量增长（10万、100万级别）
- 写入频繁的表应考虑异步处理或缓存

### 2. 表设计要求
- 每个表必须有 `created_at`、`updated_at` 字段
- 使用合适的字段类型（例如 UUID 使用 UUID 类型而非 Text）
- 避免在频繁查询的表中使用过多 JOIN
- 向量表（pgvector）必须严格控制规模和维护索引
- 关键表（如 users、agent_api_keys、skill_fragments）必须有完善的索引

### 3. 查询与性能要求
- 所有复杂查询必须先用 `EXPLAIN ANALYZE` 分析
- 高频读取场景（如排行榜、社区 feed、热门股票）必须使用 Redis 缓存
- 禁止在主线程中执行慢查询
- 重要业务逻辑应抽离到 Service 层，并考虑读写分离

### 4. 连接与资源管理
- 必须正确配置数据库连接池（SQLAlchemy + PgBouncer 推荐）
- 避免频繁创建/关闭数据库连接
- 监控数据库连接数、慢查询、CPU/内存使用情况

### 5. 安全与合规
- 敏感字段（密码、API Key 等）必须加密或哈希存储
- 所有数据库操作必须防止 SQL 注入
- 用户隐私数据严格遵守最小化原则

### 6. 修改数据库时的严格要求
- 任何数据库结构变更（加字段、加表、加索引）必须**先输出详细方案**，包括：
  - 变更影响
  - 迁移脚本
  - 回滚方案
  - 对现有数据的影响
- 优先使用 Alembic 等迁移工具
- 大表修改必须考虑零停机方案

### 7. 长期扩展考虑
- 提前规划读写分离、分库分表、向量数据库分离等方案
- 定期清理无用数据和日志
