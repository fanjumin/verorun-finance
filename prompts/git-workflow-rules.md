# 易站智能 - Git 版本控制与代码提交规范

**版本**：v2026.05-Updated  
**优先级**：高（防止代码混乱和难以回滚）

为了避免"越改越乱"和难以追踪问题，所有代码修改必须严格遵守 Git 规范。

### 1. 分支管理规范（适配实际工作流）

- **master** 分支：主开发分支，允许直接提交（适配本地/服务器独立仓库 + scp 同步架构）
- **feature/xxx**（可选）：重大新功能开发时推荐使用（如 feature/login-unify）
- **fix/xxx**（可选）：重大 Bug 修复时推荐使用（如 fix/login-sms-fail）
- **refactor/xxx**（可选）：重构时推荐使用

日常开发优先在 master 分支进行。重大功能（预计影响 5+ 文件或核心模块）时建议新建分支隔离开发，完成后合并回 master。

### 2. 提交信息规范

提交信息必须清晰、有意义，格式推荐：

```
<type>: <简短描述>

- <具体改动1>
- <具体改动2>
```

类型（type）：
- `feat`: 新功能
- `fix`: Bug 修复
- `refactor`: 重构（不影响功能）
- `style`: 样式/UI 调整
- `docs`: 文档更新

示例：
```
fix: 修复登录页面短信验证码发送失败

- 修复 feishu.py 中 token 缓存过期未刷新问题
- 添加发送失败时的用户友好提示
```

禁止无意义提交信息如 "update"、"fix bug"、"修改了一些东西"。

### 3. 代码同步规范

- 本地和服务器为**独立 git init 仓库**（非 clone 关系）
- 代码同步使用 **scp 或 rsync**，不依赖 git push/pull
- 同步前必须确认本地代码已通过测试
- 同步后必须在服务器验证功能正常

### 4. 提交节奏

- 每完成一个独立功能点后提交一次
- 禁止积攒大量修改后一次性提交
- 提交前必须确认代码可运行（前端已部署验证、后端已重启验证）
