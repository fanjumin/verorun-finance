# 易站智能 - 登录模块专项规则

**版本**：v2026.05  
**优先级**：最高（核心认证模块）

登录模块是整个平台最关键、最敏感的模块之一，必须严格遵守以下规则，杜绝反复修改导致的连锁问题。

### 1. 核心设计原则
- **全站只允许一个统一登录入口**（platform.easykai.cn 使用统一登录页面）
- 禁止创建多个重复的 login.html 或登录组件
- 所有子站（main、admin 等）的 /login 路由应 redirect 到统一登录页或调用统一组件
- 管理员后台（agent.easykai.cn）允许保留独立登录页，但必须样式统一且调用同一套认证 API

### 2. 登录方式
- 支持 Tab 切换：
  - 主要方式：手机号 + 短信验证码登录
  - 备选方式：用户名 + 密码登录
- 切换时只改变表单内容，不改变整个页面结构
- 必须包含清晰的操作说明（参考 user-flow-help-rules.md）

### 3. 安全与用户体验要求
- 严格执行强密码策略（≥12位，包含大写、小写、数字、特殊字符至少3种）
- 密码修改后必须强制所有设备下线
- 重要操作（登录、修改密码、创建 API Key）必须有安全提示文案
- 登录失败时提供友好且具体的错误提示（而非笼统的“登录失败”）

### 4. 技术要求
- 前端使用单一可复用登录组件（LoginModal 或 LoginPage）
- 后端使用统一认证 API（/auth/sms/login、/auth/password/login 等）
- 登录成功后正确处理 SSO / Token / Cookie，实现子站登录状态同步
- 必须有完善的错误处理和日志记录

### 5. 修改登录模块时的严格流程
- 任何对登录模块的修改必须**先输出完整方案**，经用户确认后才能执行
- 采用“新增新组件 → 测试通过 → 逐步替换”的最小改动方式
- 修改后必须提供详细的测试验证清单（至少包括：短信登录、密码登录、跳转、Token 有效性、管理后台登录等）

### 6. 禁止行为
- 禁止随意创建新的登录页面或组件
- 禁止在不了解全局结构的情况下直接修改登录相关代码
- 禁止一次性大范围修改登录模块

---

**执行要求**：
本规则优先级高于普通任务，与 system-core-rules.md 共同生效。任何涉及登录模块的任务都必须严格遵守。
