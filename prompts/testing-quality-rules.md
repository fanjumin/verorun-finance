# 易站智能 - 测试与质量保障规范

**版本**：v2026.05  
**优先级**：高（防止 bug 和回归问题）

为了避免“修复一个错误却引出更多错误”的情况，所有代码修改必须重视测试和质量保障。

### 1. 核心质量原则
- **预防胜于治疗**：修改前就要考虑可能的影响范围
- **测试驱动**：重要修改必须先考虑如何验证
- **逐步验证**：不允许一次性大改后才测试

### 2. 修改代码时的强制要求
每次生成或修改代码后，必须提供以下内容：

**测试验证清单**（至少包含 3-5 条具体测试点）：
- 正常流程是否正常工作
- 边界情况和错误情况处理
- 是否影响其他相关功能
- 性能是否有明显下降
- 移动端/不同浏览器是否正常

### 3. 测试类型要求
- **核心流程测试**：登录、注册、创建 Agent、生成 API Key、进入社区等必须重点验证
- **回归测试**：修改后必须确认原有功能未被破坏
- **安全测试**：涉及认证、权限、API Key 的修改必须检查安全风险
- **压力考虑**：高并发场景下是否会出现问题（如数据库连接数）

### 4. 代码审查机制
- 生成代码时优先使用清晰的 Diff 格式
- 重要模块修改必须说明：
  - 修改原因
  - 影响范围
  - 潜在风险
  - 回滚方案
- 复杂修改建议分多次小步提交

### 5. 质量检查清单
生成代码前自检：
- 是否遵守 system-core-rules.md
- 是否符合 code-style-guide.md
- 是否遵守对应模块的专项规则（如 login-module-rules.md）
- 是否添加了用户帮助说明
- 是否有足够的注释和错误处理

### 6. 长期质量目标
- 逐步为关键模块增加自动化测试（推荐 pytest 或 Jest）
- 核心功能（如登录、认证）应有相对稳定的测试用例
- 发现问题时主动记录并总结，避免同类错误重复发生

---

**执行要求**：
本规则与 system-core-rules.md 共同生效。任何代码生成或修改任务都必须提供测试验证清单和质量自检说明。
